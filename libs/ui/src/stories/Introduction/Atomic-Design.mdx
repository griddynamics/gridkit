# Atomic Design

GridKit follows **Brad Frost's Atomic Design** methodology to organize components in a hierarchical, scalable structure. This approach helps teams understand component relationships and build consistent interfaces.

## ⚛️ Atoms

**Atoms** are the foundational building blocks — basic UI elements that can't be broken down further without losing functionality. Each atom has distinct properties that influence its application.

## 🧬 Molecules

**Molecules** are simple combinations of atoms that function together as a unit. They follow the single responsibility principle — doing one thing well.

### Live Examples

</div>

## Benefits of Atomic Design

| Benefit                | Description                                                            |
| ---------------------- | ---------------------------------------------------------------------- |
| **🎯 Consistency**     | Shared atoms ensure visual harmony across the entire application       |
| **♻️ Reusability**     | Build complex UIs by composing simple, tested parts                    |
| **🔧 Maintainability** | Changes to atoms propagate predictably through molecules and organisms |
| **📈 Scalability**     | Easy to add new components at any level                                |
| **📚 Documentation**   | Clear component hierarchy makes onboarding easier                      |
| **🧪 Testability**     | Small, isolated atoms are easier to unit test                          |

## Best Practices

### 1. Start with Atoms

Always check if an atom exists before creating a new component:

```tsx
// ✅ Good - uses existing atoms
<Button variant="primary">
  <Icon name="cart" /> Add to Cart
</Button>

// ❌ Bad - creates custom button
<div className="custom-button" onClick={handleClick}>
  Add to Cart
</div>
```

### 2. Compose, Don't Duplicate

Build molecules by composing atoms:

```tsx
// ✅ Good - composes atoms
const SearchField = () => (
  <Row align="center">
    <Input placeholder="Search..." />
    <Button variant="primary">
      <Icon name="search" />
    </Button>
  </Row>
);
```

### 3. Keep Organisms Focused

Each organism should represent one distinct UI section:

```tsx
// ✅ Good - focused organism
<Header logo={...} navigation={...} actions={...} />

// ❌ Bad - too many responsibilities
<HeaderWithSidebarAndFooter ... />
```
